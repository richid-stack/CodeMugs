# 0016. The sandbox policy and the driver interface: nothing is granted that is not written down

- **Status:** Accepted
- **Date:** 2026-11-11

## Context

[ADR 0007](0007-build-the-sandbox-early.md) decided that the sandbox is a foundation, that a run is described by a typed deny-by-default policy, and that drivers sit behind one interface. This record settles what the policy and the interface are, before any driver exists, so that a driver cannot shape them by what it happens to do.

Two facts about the environment shape the first step. The engineering session has no container daemon and no KVM, so the first driver can only be tested in CI. The policy and the interface can be tested anywhere, so they come first, as a package that needs only Node.

## Decision

1. **The module is `@codemugs/sandbox-manager`, in `engineering/sandbox-manager`.** This step delivers the policy, the request and the driver interface. No driver.
2. **Deny by default, written down.** Every value of a policy is required and none has a default. A policy that leaves something out is refused, not completed. Unknown fields are refused at every level, so a typo or a field from a later version cannot be ignored silently.
3. **The policy cannot say what no driver can enforce or what must not be granted.** There is no field for network access (the network is off, and `network: { mode: "none" }` is the only value, written out so that it is a choice that was read), for credentials, a writable source, environment variables, devices or privileges. This departs from [ADR 0007](0007-build-the-sandbox-early.md) decision 3, which lists an egress allow-list and credentials. A field that nothing enforces is a promise that nobody keeps, and a driver that has to ignore or approximate it is how a policy comes to say more than the sandbox does. The allow-list and the credentials are added when there is something that enforces them and tests that show it, each as a decision of its own.
4. **Limits have a floor and a ceiling.** The floors mean that `0` can never read as "no limit". The ceilings (`SANDBOX_CEILINGS`) mean that a mistake, or a caller that should not be trusted, cannot ask for the whole host. The policy engine will decide the values a run gets (invariant 4), and the ceilings are the second line behind it. They are first values and have not been measured, and a test pins their numbers so that raising one is a change made on purpose, in two places.
5. **The image is pinned by digest, and only by digest.** A tag can be moved to other content after it was reviewed. The grammar is stricter than Docker's, and an image cannot start with a dash, so it can never be read as an option.
6. **Paths use a small alphabet.** A comma, a colon, an equals sign or a space has a meaning in a runtime's mount syntax, and a path that contains one could add an option to a mount. Refusing them in the policy means no driver has to get an escape right. Mounts on `/proc`, `/sys`, `/dev` and `/tmp` are refused (`/tmp` was added by [ADR 0020](0020-escape-and-abuse-tests.md), because the driver mounts it itself), and the source and the scratch space cannot be the same place or inside each other.
7. **A request is checked once, into a frozen copy, and a driver refuses anything else.** `validateRunRequest` returns the only object a driver accepts: a deep-frozen copy, recorded in a registry, and typed with a brand. `assertValidatedRequest` checks the registry at run time, so an object that was built by hand and cast to the type, or a copy of a checked request, is refused. What was checked is what runs: changing the original afterwards changes nothing.
8. **The host directory of the source has to be inside the workspace root,** a folder the manager keeps its working copies in. This is a check on the path as written. Resolving symbolic links before mounting is the driver's job, and is not done here.
9. **A command is a list, never a string.** It is passed to the program without a shell. It has bounds on the number of items and their length, and no item can contain a null character.
10. **The driver interface carries what a caller needs to decide.** `isolation` says what kind of driver it is (`hardened-container`, `gvisor`, `microvm`) and `isolationAtLeast` orders the levels, so the hosted tier can refuse a weaker driver ([ADR 0007](0007-build-the-sandbox-early.md) decision 5). `availability()` says whether it can run here. A driver must refuse, never relax, anything it cannot enforce.
11. **A limit that was reached is an outcome, an inability to run is an error.** A run ends as `exited`, `timed_out`, `output_limit_exceeded` or `out_of_memory`, with what the program printed up to the limit (untrusted data). `SandboxError` is for a sandbox that could not start or could not be cleaned up, and its message is a fixed sentence for the code: never what the program printed, a path, or what the runtime said.
12. **A refusal names fields and reasons, never values.** It does not print the name of a field it did not recognise either. It follows the rule of the configuration errors (invariant 3).

## Rejected alternatives

- **Model the allow-list and credentials now.** It completes the picture of [ADR 0007](0007-build-the-sandbox-early.md) and makes the first driver look incomplete for refusing them. The first driver would refuse them, and a policy that every driver refuses is not a policy.
- **Defaults for the limits.** Convenient, and a default is exactly the thing that is quietly wrong when a workload is different.
- **Let the driver validate the policy it is given.** Each driver would then carry its own copy of the rules, and the first one to forget one is the escape.
- **A deny-list of host paths for the source directory.** A deny-list is a list of what someone thought of. A folder the manager owns is a list of what is allowed.
- **Tags and digests both allowed.** The tag would be ignored by Docker next to a digest, and read by a person as the thing that runs.

## Not decided, or not done

- **No driver, so no isolation.** Nothing in this repository may claim that code runs isolated. Release gate 8 stays not started.
- **No network allow-list, no credentials.** An agent runtime in a sandbox cannot reach a model API until they exist ([ADR 0003](0003-integrate-existing-agent-runtimes.md)).
- **No contract test suite for drivers yet.** It will be written with the first driver, so that it describes what a real driver does and not a guess.
- **Nothing produces policies.** The policy engine does not exist yet, and until it does, invariant 4 is a rule of the design and not something the code enforces.
- **The ceilings, the floors and the limits on a command are first values.** They have not been measured against real workloads or real drivers.
- **The workspace root check is on the path as written.** Symbolic links are for the driver (decision 8).
- **A run has no way to give back files.** Only what the program prints is returned. When something needs to produce an artifact, it is a decision of its own.

## Evidence so far

- On 2026-11-11, with database tests required, `pnpm verify` passed against PostgreSQL 18.6: 805 tests in all (8 event schemas, 25 configuration, 17 logging, 143 storage, 83 auth, 27 migrate, 102 jobs, 97 ingestion, 100 API, 40 worker and 163 sandbox manager), none skipped, plus the smoke test, a check of every relative link in the docs (269, none broken) and the dependency audit (no known vulnerabilities). The sandbox manager's tests need only Node and ran without a container runtime.
- The tests cover each rule from both sides, accepted at the edge and refused just past it: every required field missing (named in the refusal), every limit at its floor and ceiling and just outside them, fractions, `NaN`, infinities and text where numbers belong; the ceilings' numbers; fifteen fields that would ask for more (credentials, privileges, capabilities, a user, environment, devices, host network, a writable source, a host path, the container runtime's socket, a network allow-list) refused at the level where they were put, and every network mode other than none; images accepted (with a registry and a port, nested names) and refused (a tag, `latest`, a name alone, a tag next to a digest, short, long, capital or other-algorithm digests, an option, a space, a newline, a semicolon, a URL scheme, a name that is too long); paths that could change how a mount is read (comma, colon, equals sign, space, newline, null, quote, backslash, dollar, asterisk), paths that are not plain or absolute, the runtime's own places (and places that only start like them, which are allowed), and a source and a scratch space that overlap (and ones that only share the start of a name, which do not); the frozen copy (changing the input afterwards, changing the result); a request that is not an object, has a field it should not, has a command that is empty, a string, not all text, with an empty program, with a null character, too long or with too many items (and the largest allowed, and shell characters, which are only data); a source directory that is missing, given when there is no mount, relative, the workspace itself, the whole host, outside, next to it with the same beginning, going up out of it, or with a character that could add a mount option; a workspace root that is not plain; the registry that makes `assertValidatedRequest` refuse an object built by hand, a copy and a clone of a checked request, and a type check that a plain object is not a checked request; that a refusal names fields and never values or unknown field names; the order of the isolation levels; and the fixed sentences of `SandboxError`.
- Eighty-nine deliberate breakages were made one at a time and each is caught by at least one test (or by the type check of the tests): each ceiling raised in the constants and ignored in the schema, each floor lowered, fractions allowed in whole numbers, an image with text around it or in capitals or with another algorithm or with only a tag or very long, every character that could change a mount (comma, colon, space), a relative path, no end to a path, `.` and `..` allowed, the start-of-the-name mistake in the path test, each of the three runtime places allowed, each way the source and the scratch space may overlap, every level of the schema that allows unknown fields, a network mode other than none or none at all, a source mount that is required, the policy not frozen or frozen only on top or the same object that was passed in, a refusal that prints an unknown field's name or does not say where, each limit of a request raised or off by one, an empty command or an argument that is not text or an empty program or a null character, the caller's own command being the one that runs and not being frozen, a request that is not frozen, unknown fields or an array accepted, a bad workspace root not noticed, each way a source directory could be wrong, a hand-built request accepted, a checked request not recorded or without its brand, the order of the isolation levels, and a `SandboxError` that does not carry its code, is not named or says the same for every code. Three did not compile the first time (an unused variable) and were rewritten. The run was manual and is not automated. It cannot show that the rules are enough, only that the tests notice when one is taken away.
- CI runs the same tests on PostgreSQL 17 and 18. Its result is recorded on the pull request that accepted this decision.
