# Gaps and open questions

The architecture is detailed about the intelligence core and says little about the items below. **None of these are decided.** Each needs an owner's decision. "Decide by" is the latest phase at which leaving it open starts to cost us.

| #   | Gap                                                                         | Why it matters                                                                                                                                                                                                                     | Suggested direction                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Decide by                                                                     |
| --- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 1   | Approval surface                                                            | Autonomy levels 2 and 3 depend on humans approving work, and "escalate to a human" needs somewhere to happen. The frontend is deferred until the engine is solid.                                                                  | The API exposes approvals regardless of the surface. Pull request review is the natural first surface for code changes. Deployments, migrations and permission changes need a defined path.                                                                                                                                                                                                                                                                                                                                                                                                           | Phase 4                                                                       |
| 2   | Notification channels                                                       | Escalations, approvals and incident updates need destinations such as email, chat and paging.                                                                                                                                      | Define a notification abstraction early and add channels as connectors.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Phase 4                                                                       |
| 3   | Operator and support access                                                 | Our own staff will sometimes need to see tenant data. Unrestricted access would undermine the tenant isolation promise.                                                                                                            | Time-bound, approved, fully audited break-glass access, visible to the customer. Settle this before the audit log schema is final.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Phase 1                                                                       |
| 4   | Tenant offboarding                                                          | When a customer leaves or disconnects we must revoke credentials and delete source snapshots, telemetry and derived data across every store (release gate 15).                                                                     | Model deletion as a first-class workflow with verification, not a script.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Phase 1-2                                                                     |
| 5   | Data classification and retention                                           | Retention periods, and which data may be sent to model providers, are undecided. See the [data classification draft](../security/data-classification.md).                                                                          | Decide defaults, then make every store support them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Phase 1                                                                       |
| 6   | Model providers as sub-processors                                           | Prompts may contain source code, logs and personal data. Provider retention terms and regional processing matter to customers and to compliance.                                                                                   | Review provider data terms before any customer data is sent. Give each tenant control over which providers and which data classes may be used.                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Phase 1                                                                       |
| 7   | Data residency and regions                                                  | The architecture mentions "data residency options" but not how. It shapes storage, queues and the model gateway.                                                                                                                   | Keep region a first-class attribute of a tenant even if only one region exists at first.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Phase 1                                                                       |
| 8   | Environments and release process                                            | Dev, staging and production for the platform itself, how migrations ship, feature flags, rollbacks.                                                                                                                                | Decide the promotion path and a migration policy (expand, then contract) before the first deployment.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Phase 1                                                                       |
| 9   | Availability and recovery targets                                           | Backups and disaster recovery are release gate 14 but have no targets: service level objectives, recovery point and recovery time objectives.                                                                                      | Set targets early, since they drive architecture more than late hardening does.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Define in Phase 1, prove in Phase 7                                           |
| 10  | Quotas, metering and billing                                                | The control plane lists billing and release gate 17 needs budgets. Ingestion volume and model spend need per-tenant limits.                                                                                                        | Model quotas and usage metering from the start, even before billing exists.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Phase 1                                                                       |
| 11  | Public API surface and versioning                                           | Which interfaces are public (SDK ingestion, REST, outbound webhooks) and how they are versioned and deprecated.                                                                                                                    | See the [API conventions](../api/conventions.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Phase 1-2                                                                     |
| 12  | Analysing untrusted repositories, and which isolation the hosted tier needs | Cloning customer code is fine. Parsing it is attack surface, and running package managers, build scripts or test suites on it is code execution.                                                                                   | Decided in [ADR 0007](decisions/0007-build-the-sandbox-early.md): the sandbox is built in Phases 1-2 and all analysis of customer code runs inside it. Still open: whether gVisor or a microVM is needed for the hosted multi-tenant tier. Settle it with a spike.                                                                                                                                                                                                                                                                                                                                    | Phase 2                                                                       |
| 13  | Repository access model                                                     | How we authenticate to source control sets the blast radius of a credential leak.                                                                                                                                                  | Prefer a GitHub App with narrow read-only permissions, widened per autonomy level, over broad personal tokens. Confirm against GitHub's current permission model.                                                                                                                                                                                                                                                                                                                                                                                                                                     | Phase 2                                                                       |
| 14  | Evaluation data                                                             | Evaluating diagnoses and agents needs real incidents with known outcomes.                                                                                                                                                          | Start collecting labelled incidents early, with OpenLobs as the first source.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Collect in Phase 2, use in Phase 4                                            |
| 15  | Telemetry volume model                                                      | When Postgres stops being the right home for events (ADR 0005) depends on real volume.                                                                                                                                             | Measure ingest rate and storage growth in Phase 3 and set the ClickHouse trigger from data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Phase 3                                                                       |
| 16  | Customer visibility into decisions                                          | Customers will want to see why the platform acted, and to export it.                                                                                                                                                               | Treat the evidence ledger as customer-facing from the start.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Phase 4                                                                       |
| 17  | Software licence and dependency licence policy                              | The code is proprietary: all rights reserved, see [LICENSE](../../LICENSE). Self-hosted enterprise packaging (ADR 0002) and any customer-embedded SDK need defined terms. Some dependency licences restrict how we can distribute. | Stay all-rights-reserved while deciding. Candidates: Apache-2.0 for the SDKs and anything embedded in customer applications; for the engine, either the Functional Source License (bars competing use, converts to Apache-2.0 after two years) or AGPL-3.0 with a commercial licence, which needs a CLA before any outside contribution is accepted. A licence on a published version generally cannot be withdrawn from copies already distributed, so decide before the first outside contribution or customer deployment. Add dependency licence scanning to CI before the first external release. | Before any outside contribution, customer deployment or self-hosted packaging |

Gap 12 is also recorded in the [threat model](../security/threat-model.md).
